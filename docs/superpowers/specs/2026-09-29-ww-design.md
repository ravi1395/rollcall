# ww — "where was I" across repos and agent sessions

**Status:** DRAFT — brainstorming in progress. Sections 1–2 approved; Sections 3+ pending.
**Date:** 2026-09-29
**Name:** `ww` is a working name; final name decided before first release.

## 1. Brief (approved)

### Problem

Developers running AI coding agents (Claude Code, Codex) across many repos lose track of where they were:

- **Agent context lost** — which session touched which repo/branch, what it was doing, what was decided.
- **Repo sprawl** — dirty trees, unpushed commits, branches without upstreams, stale worktrees.
- **Notes ↔ code gap** — deferred to a later adapter (see Roadmap).

Existing tools (claude-mem, `.remember`, `/handoff`, `/repo-debt-report`, graphify) are **per-project**. None gives one cross-repo view. That cross-repo view is the differentiator.

### Grounding data (author's machine, 2026-09-28)

- 15 git repos + 14 worktrees under `~/Projects`.
- 1,972 Claude Code session logs (`~/.claude/projects/*/*.jsonl`); records carry `cwd` and `gitBranch`.
- 1,403 Codex session logs (`~/.codex/sessions/**.jsonl`); `session_meta` record carries `cwd`.
- No local Cursor session logs found.

### Audience

AI-agent developers working across several repos. Obsidian is **not** required.

### What makes it fun (author goals)

Delightful UX (demo-able TUI), a hard technical core (incremental parsing, indexing), a new stack (Rust), and a fast first ship.

### Decided

| Decision | Choice |
|---|---|
| Language | Rust |
| Audience | AI-agent devs |

### Assumptions

- Session log formats are undocumented and can change without notice; parsers must fail soft.

## 2. Approaches considered

- **A. Scan on demand + cache (chosen).** Zero-config, reads existing history on first run, weekend-sized v0. Freshness equals last scan.
- **B. Daemon + live index.** Live TUI, but install/lifecycle friction and ~2–3× v0 scope. Planned as v1 upgrade behind the `Index` trait.
- **C. Agent hooks write a ledger.** Exact but needs per-agent setup and misses history. Possible future optional source.

## 3. Scope and components (approved — Section 1)

### Commands

- `ww` — TUI.
- `ww status [--json]` — table for scripts/agents.
- `ww mcp` — stdio MCP server; tools `where_was_i(repo?)`, `list_stale()`.
- `ww scan --root <path>` — optional explicit scan; default root from config, else `~`.

### Per repo → branch/worktree

- Branch, ahead/behind upstream, dirty file count, unpushed commits, no-upstream flag.
- Stale worktrees: branch merged into default, or no commits in N days.
- Last agent session on that repo+branch: tool (Claude/Codex), time ago, title or first prompt, last user prompt, message count.
- Attention sort: unpushed > dirty > stale > quiet.

### Workspace crates

| Crate | Responsibility |
|---|---|
| `ww-core` | Domain types (`Repo`, `Worktree`, `Session`, `Attention`), `Index` trait, query API. No I/O. |
| `ww-git` | Repo discovery + status via `gix`, parallel via `rayon`. |
| `ww-sessions` | `SessionSource` trait; `claude` and `codex` impls; offset-based JSONL reads; `cwd`+`gitBranch` → worktree match. |
| `ww-store` | SQLite (`rusqlite`) cache implementing `Index`; migrations. |
| `ww-cli` | `clap` commands, `ratatui` TUI, `rmcp` MCP server — all over the same core query API. |

### Out of v0 (roadmap)

Daemon/watcher (B), LLM session summaries, Obsidian adapter, Cursor source, hook source (C), decision-journal integration.

## 4. Data flow and error handling (approved — Section 2)

### Scan pipeline

Runs on `ww scan`, and implicitly before `status` / TUI / MCP queries when the cache is older than N seconds.

1. **Discover repos:** parallel walk of the root. Skip `node_modules`, `target`, `.venv`, hidden dirs other than `.git`; bounded max depth. Worktrees come from `git worktree list`, not the walk.
2. **Git status per worktree** via `gix`. A failing repo gets an `Error` state row; the scan continues.
3. **Sessions:** per source, list log files and compare stored `(path, inode, size, offset)`.
   - Size grew → read from stored offset.
   - Inode changed or size shrank → re-read from 0.
   - Partial trailing line → stop before it; do not advance offset.
4. **Match session → worktree:** longest-prefix match of session `cwd` against known worktree paths. Branch from record `gitBranch`, else the worktree's current branch. No match → `orphaned`.
5. **Store:** one SQLite transaction per scan. Queries read committed state only.

### Format drift

- Unknown record types and malformed lines are skipped and counted.
- Each source stores `parser_version`; bumping it forces re-parse from offset 0.
- `ww doctor` reports per source: files, records, skipped lines, orphans — a format change shows as a spike, not silent bad data.

### Privacy

- Read-only, fully local, no network.
- Prompt text truncated in output (default 200 chars). `redact_prompts = true` hides prompts entirely — matters because MCP hands text to whatever model is connected.

### Performance targets

- Cold scan: ~30 worktrees + ~3.4k logs in < 5 s.
- Warm scan: < 300 ms.
- Verified by a benchmark on real data plus a synthetic fixture.
