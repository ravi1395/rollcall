# rollcall Copilot CLI source — acceptance criteria (spec revision 17)

Fixed acceptance criteria for the Copilot plan `docs/superpowers/plans/2026-10-07-rollcall-copilot-plan.md`, resolved per the author's answers Q1–Q7 and R1 approval of 2026-10-07 (`HANDOFF.md`, "Author answers 2026-10-07 (Copilot plan)") and the session-15 probe of real Copilot CLI 1.0.93 sessions (`HANDOFF.md` step 1b, "Probe run" and "Probe re-run"). The spec is the contract: `docs/superpowers/specs/2026-09-29-rollcall-design.md`, revision 17 (§5.3). These criteria stay fixed through the fix loop; a criterion is met only with evidence. Phase 4 is not run (Q1 = "(a) First prompt", Q2 = "Never / later"); Phase 5 (real-data check) runs in the main loop, not here.

## Conventions (all items)

- Every command runs with `HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `COPILOT_HOME` pointed at a scratch directory and `ROLLCALL_NOW` fixed (§10.1). Never against the real `~/.claude` / `~/.codex` / `~/.copilot`.
- `$F`, `$F_clean`, `H` are the §10.1 fixture roots; new fixtures go in `tests/fixtures/MANIFEST.toml` (hand-written) and `rollcall-cli/tests/it/`. Copilot fixtures are hand-written JSONL in the key sets of spec §5.3, with prompts holding the marker string `PROMPT-MARKER`; nothing is copied from a real store.
- Each item ends with the R2 gate passing: `cargo fmt --check && cargo clippy --workspace --all-targets --locked -- -D warnings && cargo test --workspace --locked`.
- R1 for every item: `git diff --quiet <item base> -- Cargo.lock '*Cargo.toml'` exits 0, and no `mod` list or pinned interface signature changes except the item's "R1 allowed" line (author-approved 2026-10-07). A needed change is a stop-and-report, not a criterion failure to work around.
- A criterion tagged **(assumption)** rests on a spec detail marked *assumption*; it stands until the author confirms or changes that detail, and then follows the decision.
- Context-changed fixtures use the `type` string `session.context_changed`, the on-disk name the probe confirmed (spec §5.3).
- Items are implemented in order P1 → P2 → P3 (P1 adds the enum every later phase matches on; P3 wires what P2 builds). Until P3, the Copilot source is not registered and user-visible output is unchanged.
